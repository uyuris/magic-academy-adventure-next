# Project Layout

Governing artifact: this repo's documented read-only migration policy and current project layout. Keep policy references repo-local and avoid machine-specific external file paths in tracked docs.

## Purpose

This document defines the active directory layout for `magic-academy-adventure-next`.
The layout is designed to avoid the previous mixing of source docs, runtime code, generated assets, and mutable play data.

## Layout summary

- `docs/` — design, requirements, and migration control.
- `app/` — executable application code and the authored runtime shell (`app/public/`).
- `content/` — authored game-content surfaces. Character-authored profiles and appearance metadata live under `content/characters/<character_id>/`.
- `data/` — definitions, seeds, fixtures, and mutable outputs. Character runtime continuity such as `skills.json`, `flags.json`, `memory/`, and `work_records/` lives under `data/mutable/game_data/characters/<character_id>/` and under per-slot play data when a slot is active.
- `assets/` — canonical accepted assets and provenance/support artifacts. Accepted character visual sets live under `assets/canonical/character_visual_sets/`.
- `tools/` — support scripts for import, normalization, and maintenance.
- `work/` — local migration notes and reports that are not part of the runtime contract.

## Current implementation snapshot

- `app/src/server.mjs` is the runtime entrypoint.
- `app/src/server/*.mjs` holds grouped API handlers; there is no Express/Hono dependency in the current package.
- `app/src/llm/*.mjs` holds LM Studio request transport, prompt construction, validator, and conversation pipeline helpers.
- other `app/src/*.mjs` root files remain the live shared runtime/game modules; this repo does not currently claim a separate `domain/` or `persistence/` source split.
- `app/public/` is the live browser shell (`index.html`, `style.css`, `app.js`). It is not generated by a frontend build step at present.
- `app/config/` holds local runtime configuration examples, including LM Studio settings.
- `data/definitions/game_data/` contains canonical structured definitions such as locations, flags, shop catalog, and world settings.
- `data/seeds/game_data/` contains starting-state templates.
- `data/mutable/game_data/` is now an active mutable runtime/play-data area, including active-slot metadata, per-slot play data, logs, runtime state, and character continuity surfaces.

## Hard rule

This directory layout must be evolved inside this project only.
Do not reorganize the source projects in place.

## Public/runtime-export boundary

- `app/public/` holds the authored runtime shell files.
- generated browser compatibility URLs under `/generated/*` resolve from canonical-backed asset classes; they no longer require `assets/runtime_exports/`.
- `app/public/imported_runtime_staging/` may remain as migration reference material, but active runtime serving should not depend on it for root-shell or generated-export success.
